# 룬 헌터 사용법 가이드

처음 설치부터 실전 사냥까지 순서대로 따라갈 수 있게 정리했습니다.
설정 항목의 의미와 증상별 조정 방법은 4~6장, 문제 해결은 9장을 보세요.

> ⚠️ 사용에 따른 게임 약관 위반·계정 제재·손해의 책임은 사용자 본인에게 있습니다.
> 본인이 책임지는 사설 서버 환경에서만 사용하세요.

---

## 1. 준비물

| 항목 | 내용 |
| --- | --- |
| OS | Windows 10 / 11 (실제 키 입력은 Windows 전용) |
| 파이썬 | 3.10 이상 64비트 (권장 3.11 / 3.12) |
| 게임 | **창모드**로 실행. 해상도는 고정해두는 것이 좋습니다 |
| 권한 | 게임이 관리자 권한이면 매크로도 관리자 권한 필요 (자동 승격됨) |

설치:

```bat
cd C:\code
git clone <저장소 주소> rune-hunter
cd rune-hunter
run.bat
```

`run.bat` 이 처음 실행될 때 `.venv` 가상환경을 만들고 PySide6 / OpenCV / numpy / mss 를 설치합니다.
설치가 끝나면 UAC(관리자 권한) 창이 뜨므로 **예**를 누릅니다.

- 게임 없이 동작만 먼저 보려면: `run_demo.bat`
- 이후 실행은 항상 `run.bat` 하나로 끝납니다.

## 2. 5분 빠른 시작 체크리스트

1. [ ] 게임을 **창모드**로 실행하고 사냥할 맵에 캐릭터를 세워둡니다.
2. [ ] `run.bat` 실행 → 관리자 권한 승인.
3. [ ] 오른쪽 위 카드에 `프로세스 발견됨! <창 제목> (프로세스명, PID)` 이 보이는지 확인.
       안 보이면 → 6장의 **창 제목 검색어** 수정.
4. [ ] `자동공격` 탭에서 사냥기 키와 주기를 설정하고, 쓰는 버프에 체크.
5. [ ] `룬 해제` 탭에서 템플릿 5장(룬 + 화살표 4방향)을 `화면에서 캡처` 로 만듭니다.
6. [ ] `지금 화면에서 룬 감지 테스트` / `화살표 판독 테스트` 로 점수 확인.
7. [ ] `성능 · 설정` 탭 → `설정 저장`.
8. [ ] `성능 · 설정` 탭에서 **데모 모드 켜고** `시작` → 로그로 로직 확인 → `중지` → 데모 모드 끄기.
9. [ ] 게임 창을 클릭해서 활성화하고 `F1`. 정지는 `F2`.

## 4. 자동공격 탭

각 줄은 `[체크박스] 이름 — 입력 키 — 주기` 구조입니다. 체크를 끄면 그 키는 아예 사용하지 않습니다.

| 항목 | 의미 | 기본값 | 권장 |
| --- | --- | --- | --- |
| 사냥기 | 시간제한 없이 계속 반복하는 주력기 | `U` / 0.12초 | 스킬 후딜에 맞춰 0.08~0.25초 |
| 사냥키를 누른 상태로 유지 | 연타 대신 키를 계속 누름 | 꺼짐 | 홀드로 연사되는 스킬이면 켜기 |
| 보스기 | 쿨타임 있는 강한 스킬 | `W` / 8초 | 실제 쿨타임보다 0.5초 길게 |
| 버프 1~6 | 주기마다 자동 사용 | 버프1 `Q`/120초, 버프2 `W`/180초 | 지속시간보다 10~20초 짧게 |
| 시작 직후 버프 사용 | 시작할 때 켜둔 버프를 한 번씩 사용 | 켜짐 | 그대로 |
| 사냥 중 이동 | 주기적으로 좌우 이동(+점프) | 꺼짐 | 한 자리 사냥이면 꺼두기 |
| 점프 / 로프 커넥트 | 룬 접근에 사용하는 이동 키 | `ALT` / `A` | 게임 키설정과 맞추기 |

동작 규칙 몇 가지를 알아두면 설정이 쉽습니다.

- **우선순위는 룬 해제 > 버프 > 보스기 > 사냥기** 입니다. 같은 순간에 겹치면 버프가 먼저 나갑니다.
- 사냥기 주기는 "이전 예정 시각 + 주기" 로 계산해서, 오래 돌려도 주기가 밀리지 않습니다.
- 룬 해제나 창 비활성으로 멈춰 있던 동안 주기가 지난 버프는, 재개 직후 **한 번만** 사용합니다
  (밀린 횟수를 몰아서 연타하지 않습니다).
- 아래 점프는 `아래 방향키 + 점프키` 조합으로 자동 처리되므로 따로 설정할 것이 없습니다.

## 5. 룬 해제 탭 (가장 중요)

![룬 해제 탭](screenshot_rune.png)

### 5-0. 먼저 룬 찾는 방식을 고릅니다

| 방식 | 동작 | 언제 쓰나 |
| --- | --- | --- |
| **미니맵 색상** (기본, 권장) | 미니맵의 **보라색 룬 표식**과 **노란색 캐릭터 표식**이 겹치도록 이동한 뒤 활성화 키를 누릅니다 | 룬이 화면 밖 다른 지점에 생기는 일반적인 경우 |
| 화면 템플릿 | 화면에 보이는 룬 이미지를 찾아 접근합니다 | 룬이 항상 한 화면 안에 보이는 좁은 맵 |

**미니맵 모드 설정 순서** (룬이 하나 떠 있는 상태에서 하면 편합니다)

1. `룬 찾는 방식` → `미니맵 색상으로 찾기` 체크
2. `미니맵 영역` → `영역 지정` → 게임 화면에서 **미니맵 전체**를 드래그
3. `룬 표식 색` → `룬 색 추출` → 미니맵의 **보라색 룬 표식만** 작게 드래그
4. `캐릭터 표식 색` → `캐릭터 색 추출` → 미니맵의 **노란색 내 캐릭터 점만** 작게 드래그
5. `해제 동작` 의 `룬 활성화 키` 를 실제 키로 설정 (이 서버는 **SPACE**)
6. `미니맵 인식 테스트` 를 눌러 로그 확인 →
   `미니맵 인식 성공 — 룬 (87, 44) / 캐릭터 (90, 55) → dx -3, dy -11` 처럼 나오면 완료
7. 화살표 템플릿 4장은 여전히 필요합니다 (5-1 참고). 룬 이미지는 미니맵 모드에서 쓰지 않습니다

**겹치면 보라색이 가려집니다.** 캐릭터(노랑)가 룬(보라) 위에 올라가면 미니맵에서 보라색 표식이
노란색에 덮여 보이지 않습니다. 매크로는 이 상황을 "사라짐"이 아니라 **위치 일치**로 판단합니다.
직전 좌우 차이와 방금 이동한 거리로 현재 위치를 추정하고, 그래도 애매하면 화면에 룬이 보이는지로
확인합니다. 로그에 이렇게 남습니다.

```
미니맵 이동: 왼쪽 135ms (dx -3.0, dy -11.0)
미니맵 이동: 로프 커넥트로 상승 (dx +1.0, dy -11.0)
룬 표식이 캐릭터에 가려짐 (추정 dx +1.0) → 위치 일치로 판단
화면에서 룬 확인 (점수 1.00) → 템플릿으로 미세 정렬
룬 활성화 입력 1/2 (SPACE)
```

멀리서 표식이 사라지면(다른 사람이 먹었거나 만료) 그대로 실패 처리하고 사냥으로 복귀합니다.

**정렬 동작**: `dx`(좌우 차이)가 `좌우 정렬 허용 오차`(기본 2px) 안에 들어올 때까지 방향키를 누르고,
`dy`(높이 차이)가 남아 있으면 위쪽이면 로프 커넥트(`A`), 아래쪽이면 아래+점프로 이동합니다.
미니맵 1픽셀이 실제로 몇 ms 이동인지는 맵마다 다르므로, **이동할 때마다 실제 이동량을 측정해
계수를 자동 보정**합니다(`이동 계수 자동 보정`). 처음 한두 번은 크게 움직이다가 곧 정확해집니다.

로그 예시:

```
미니맵에서 룬 발견 (룬 (87, 44) / 캐릭터 (90, 55) → dx -3, dy -11) → 스킬 입력 중단
미니맵 이동: 왼쪽 135ms (dx -3, dy -11)
미니맵 이동: 로프 커넥트로 상승 (dx 1, dy -11)
미니맵 정렬 완료 (dx 2, dy 0, 계수 40ms/px)
룬 활성화 입력 1/2 (SPACE)
화살표 판독: ↑ ↓ ↑ ↑
룬 해제 성공 (↑ ↓ ↑ ↑) → 사냥/버프 재개
```

### 5-0-1. 화살표 템플릿은 1장만 캡처하면 됩니다

게임의 화살표 4개는 **같은 그림을 90도씩 돌린 것**입니다. 그래서
`화살표 1장으로 4방향 자동 생성` 버튼을 쓰면 한 방향만 캡처하고 나머지는 자동으로 만듭니다.

1. 룬을 활성화해서 `룬을 해방하려면 방향키를 순서대로 입력하세요` 패널이 떠 있는 상태로 만듭니다
2. `화살표 1장으로 4방향 자동 생성` → 화살표 **하나**만 테두리에 맞게 드래그
3. 그 화살표가 어느 방향인지 선택 → `arrow_up/down/left/right.png` 4장이 자동 생성됩니다
4. `화살표 판독 테스트` → 로그에 판독 결과와 **방향별 최고 점수**가 나옵니다

```
화살표 판독: → ↑ ↑ ↓  (12.4ms)
방향별 최고 점수: DOWN 0.91, LEFT 0.88, RIGHT 0.93, UP 0.95 (임계값 0.70)
```

점수가 임계값보다 낮으면 `화살표 감지 임계값`을 그 아래로 내리거나 캡처를 다시 하세요.

### 5-0-2. 상단 안내 문구로 감지하기 (선택)

`엘리트 보스의 저주…` 문구는 룬이 남아 있는 동안 계속 떠 있고 해제되면 사라집니다.
그래서 **룬 등장 감지**와 **해제 성공 판정** 모두에 쓸 수 있는 가장 확실한 신호입니다.

1. 문구가 떠 있는 상태에서 `문구 캡처` → 문구의 **글자 부분**을 드래그
   (해제 완료 메시지와 헷갈리지 않도록 `룬을 해방하여` 처럼 이 상태에만 나오는 글자를 고르세요)
2. `상단 안내 문구로 룬 등장·해제 판정` 체크

이걸 켜면 미니맵 색 인식이 잘 안 되는 순간에도 룬 등장을 놓치지 않고,
해제 성공 여부도 문구가 사라졌는지로 정확히 판정합니다.

### 5-1. 템플릿 만들기 (수동)

이미지 인식 기반이라 **본인 서버 화면으로 만든 템플릿**이 있어야 정확합니다.

1. 사냥터에 룬이 하나 떠 있는 상태로 만듭니다.
2. `룬 이미지` 줄의 `화면에서 캡처` → 게임 화면이 뜨면 **룬만** 드래그해서 선택 → `선택 영역 사용`.
3. 룬을 실제로 활성화해서 화면 상단에 방향 화살표가 떠 있게 만듭니다.
4. `화살표 위 ↑` ~ `화살표 오른쪽 →` 4줄을 각각 캡처합니다.
   화면에 떠 있는 화살표 중 해당 방향인 것을 골라 **글리프에 딱 맞게** 자르세요.
5. 저장된 파일은 `templates/` 폴더에 들어갑니다(`rune.png`, `arrow_up.png` …).

잘 되는 템플릿의 조건: 배경 최소화, 20~60px 크기, 반짝이는 중간 밝기 프레임.
해상도를 바꾸면 템플릿을 다시 만들어야 합니다.

### 5-2. 탐색 영역 지정 (속도 + 정확도)

`영역 지정` 버튼으로 드래그해서 범위를 좁힙니다. 화면 비율로 저장되므로 창 크기가 조금 달라져도 유지됩니다.

- **룬 탐색 영역**: 룬이 나타날 수 있는 범위. 보통 화면 대부분(기본 위쪽 90%).
- **화살표 탐색 영역**: 방향 화살표가 뜨는 상단 중앙. 여기를 좁히면 판독이 눈에 띄게 빨라집니다.

### 5-3. 감지 설정

| 항목 | 기본값 | 이럴 때 조정 |
| --- | --- | --- |
| 룬 감지 임계값 | 0.72 | 룬을 못 찾으면 ↓ (0.60까지), 룬이 없는데 감지되면 ↑ |
| 화살표 감지 임계값 | 0.70 | 4개 중 일부만 인식되면 ↓ |
| 룬 탐색 주기 | 0.60초 | CPU 를 더 아끼려면 1.0초로 ↑ |
| 화살표 개수 | 4개 | 서버가 다른 개수를 쓰면 변경 |
| 판독 확정 프레임 | 2 | 판독이 흔들리면 3으로 ↑ (같은 결과가 N번 나와야 입력) |
| 감지 축소 배율 | 1.00배 | 0.5로 낮추면 룬 탐색이 3~4배 빨라짐. 인식률이 떨어지면 0.7 |

### 5-4. 해제 동작

| 항목 | 기본값 | 설명 |
| --- | --- | --- |
| 룬 활성화 키 | `↑ 위` | 룬 앞에서 눌러 방향 입력 UI 를 띄우는 키 |
| 활성화 시도 횟수 | 2회 | UI 가 안 뜨면 다시 시도. **UI 가 이미 떠 있으면 누르지 않습니다** |
| 화살표 키 누름 시간 | 45ms | 입력이 씹히면 60~80ms 로 ↑ |
| 화살표 입력 간격 | 0.16초 | 서버 반응이 느리면 0.2~0.3초로 ↑ |
| 화살표 UI 대기 | 2.5초 | UI 가 늦게 뜨는 서버면 ↑ |
| 해제 확인 대기 | 3.0초 | 성공 판정을 기다리는 시간 |
| 재시도 횟수 | 2회 | 실패 시 다시 활성화해서 재시도 |
| 성공/실패 후 재탐색 대기 | 8초 / 20초 | 해제 후 곧바로 다시 룬을 찾지 않게 쉬는 시간 |

성공 판정은 **화살표 UI 가 사라지고 룬까지 없어졌을 때**만 내려집니다.
순서를 틀리면 게임은 UI 만 닫고 룬을 남기는데, 이 경우 실패로 보고 다시 활성화해서 재시도합니다.

### 5-5. 룬 접근 (룬이 멀리 있을 때)

| 항목 | 기본값 | 설명 |
| --- | --- | --- |
| 접근 동작 사용 | 켜짐 | 끄면 이동 없이 제자리에서 활성화만 시도 |
| 좌우 허용 오차 | 30px | 이 안에 들어오면 정렬 완료로 판단 |
| 이동 환산 계수 | 2.2 ms/px | 1픽셀 이동에 방향키를 몇 ms 눌러야 하는지 |
| 1회 최대 이동 | 700ms | 한 번에 방향키를 누르는 최대 시간 |
| 높이 차 허용 | 60px | 이보다 높이 차가 크면 로프/아래점프 사용 |
| 접근 제한 시간 | 12초 | 이 시간 안에 못 붙으면 포기하고 실패 처리 |
| 위로 이동 시 로프 커넥트 | 켜짐 | 끄면 점프로 올라감 |

**이동 환산 계수 보정 방법**: 캐릭터 이동 속도에 따라 다릅니다.
로그의 `룬 접근: 오른쪽 350ms (x차이 160px)` 같은 줄을 보면서

- 룬을 **지나쳐 버리면** 계수를 낮춥니다 (2.2 → 1.6)
- 여러 번 조금씩만 움직이면 계수를 올립니다 (2.2 → 3.0)

접근이 계속 불안하면 `접근 동작 사용`을 끄고, 룬이 화면에 보이는 위치에서 사냥하는 방식이 더 안정적입니다.

### 5-6. 테스트 버튼 3개

| 버튼 | 하는 일 |
| --- | --- |
| 지금 화면에서 룬 감지 테스트 | 현재 게임 화면에서 룬을 찾아 점수·좌표·소요시간을 로그에 출력 |
| 화살표 판독 테스트 | 화살표 4개를 읽어 `→ ↑ ↑ ↓` 형태로 출력 |
| 현재 화면 저장 | 지금 화면을 `logs/` 에 PNG 로 저장 (인식 실패 원인 분석용) |

목표: 룬 감지 점수 **0.85 이상**, 화살표 판독이 화면에 보이는 순서와 **정확히 일치**.

## 6. 성능 · 설정 탭

![성능 설정 탭](screenshot_perf.png)

### 게임 창

- **창 제목 검색어**: 쉼표로 여러 개를 넣을 수 있고, 제목의 일부만 일치해도 됩니다.
  작업 관리자에서 실제 창 제목을 확인해 넣으세요 (예: `나루`). 여러 개가 걸리면 가장 큰 창을 고릅니다.
- **게임 창이 활성화된 경우에만 키 입력**: 켜두는 것을 강력히 권장합니다.
  다른 창을 보는 동안 키가 그쪽으로 들어가는 사고를 막아줍니다. 비활성이면 누르던 키도 놓습니다.
- **제어 루프 주기**: 기본 4ms. 늘리면 CPU 를 아끼고, 줄이면 주기 정확도가 약간 좋아집니다.

### 단축키

시작 `F1` / 정지 `F2` 가 기본입니다. **전역 단축키로 등록되므로 그 키는 게임에서 사용할 수 없게 됩니다.**
게임에서 F1/F2 를 쓴다면 `F11`, `F12`, `INSERT`, `END` 등으로 바꾸고 `단축키 다시 등록`을 누르세요.

### 데모 모드

가짜 게임 화면에 룬이 등장하는 시뮬레이션입니다. **실제 키는 게임으로 전송되지 않습니다.**
설정을 바꾼 뒤 로직을 확인하거나, 접근·판독·재시도 흐름을 눈으로 보고 싶을 때 사용합니다.
데모 모드에서는 템플릿이 없어도 합성 이미지로 동작합니다.

### 성능 · 통계 읽는 법

| 항목 | 정상 범위 | 이상하면 |
| --- | --- | --- |
| 루프 지연 (평균/최대) | 평균 1ms 이하 | 크면 다른 무거운 프로그램 종료, 제어 루프 주기 조정 |
| 감지 시간 (평균/최대) | 10ms 이하 | 크면 탐색 영역 좁히기 / 감지 축소 배율 0.5 |
| 룬 해제 (성공/시도) | 시도 대비 성공 | 실패가 많으면 5-3, 5-4 조정 |
| 키 입력 | 사냥기 횟수 ÷ 가동 시간 ≈ 설정 주기 | 크게 다르면 창 비활성/룬 해제 시간 확인 |

### 프로필

`설정 저장`은 `profiles/default.json` 에 저장되어 다음 실행 때 자동으로 불러옵니다.
캐릭터별 설정은 `다른 이름으로 저장` → `설정 불러오기` 로 관리하세요.

## 7. 실전 운영 순서

1. 게임 실행 → 창모드 확인 → 사냥터로 이동, 캐릭터를 사냥 위치에 세웁니다.
2. `run.bat` 으로 매크로 실행 (관리자 권한 승인).
3. 상태 카드에 창 정보가 보이는지, 로그에 `관리자 권한으로 실행 중` 이 있는지 확인합니다.
4. **게임 창을 클릭해서 활성화**한 뒤 `F1`.
5. 로그에 `매크로 시작 — 활성 키: 사냥기, 버프1 …` 과 버프 사용 기록이 흐르면 정상입니다.
6. 정지는 `F2` 또는 `중지` 버튼. 정지 시 누르고 있던 키는 모두 놓습니다.

## 9. 증상별 해결

| 증상 | 원인과 조치 |
| --- | --- |
| 키가 게임에 전혀 안 들어감 | ① 관리자 권한으로 실행했는가 ② 게임 창이 활성 상태인가 ③ 로그에 `SendInput 실패` 가 있는가 |
| 창을 못 찾음 | 창 제목 검색어를 실제 제목의 일부로 수정 (작업 관리자에서 확인) |
| 사냥은 되는데 룬을 못 찾음 | 템플릿 재캡처 → `룬 감지 테스트` 점수 확인 → 임계값 0.65 정도로 ↓. 해상도를 바꿨다면 템플릿 재생성 |
| 룬이 없는데 감지됨(오탐) | 임계값 ↑, 룬 탐색 영역 좁히기, 배경이 적게 들어간 템플릿으로 교체 |
| 화살표를 2~3개만 인식 | 화살표 템플릿을 더 정확히 자르기, 화살표 임계값 ↓, 탐색 영역이 4개를 모두 덮는지 확인 |
| 판독은 맞는데 해제가 안 됨 | 화살표 키 누름 시간 60~80ms, 입력 간격 0.2~0.3초로 ↑ |
| 룬에 접근하다 지나침 | (템플릿 모드) 이동 환산 계수 ↓ (2.2 → 1.6). (미니맵 모드) `이동 계수 자동 보정`을 켜두면 스스로 맞춥니다 |
| 룬 위로 못 올라감 | 로프 커넥트 키가 게임 설정과 같은지 확인, 높이 허용 오차 조정 |
| `미니맵에서 캐릭터 표식을 찾지 못했습니다` | `캐릭터 색 추출`을 다시 하고, 미니맵 영역이 표식을 포함하는지 확인 |
| `룬 색과 캐릭터 색 범위가 N% 겹칩니다` | **가장 흔한 실수**입니다. 두 색을 각각 다시 추출하세요. 겹치면 같은 표식을 둘 다로 인식해 `dx 0` 이 되고, 정렬된 것으로 착각합니다. `미니맵 인식 테스트` 는 이 상태를 빨간 오류로 알려줍니다 |
| `dx` 가 항상 0 으로만 나온다 | 위와 같은 원인입니다. `logs/minimap_debug.png` 를 열어 빨강(룬)과 초록(캐릭터) 표시가 서로 다른 위치인지 확인하세요 |
| 정렬은 됐다는데 스페이스바가 안 먹는다 | 몇 픽셀 어긋난 것입니다. `활성화 시도 횟수`를 3~4로 올리면 실패할 때마다 조금씩 움직여 다시 시도합니다. `좌우 정렬 허용 오차`는 1px 권장(0 은 내부적으로 0.5px 로 처리) |
| `미니맵에서 룬 표식이 사라졌습니다` | 다른 사람이 먹었거나 룬이 만료된 경우입니다. 정상 동작이며 사냥으로 복귀합니다 |
| `이동해도 미니맵 표식이 변하지 않습니다` | 벽/모서리에 막힌 경우입니다. 사냥 위치를 조정하거나 `1회 최대 이동`을 늘려보세요 |
| 사냥 주기가 설정보다 느림 | 통계의 루프 지연 확인. 룬 해제 시간은 사냥 시간에서 빠지므로 어느 정도 차이는 정상 |
| CPU 사용률이 높음 | 탐색 영역 좁히기 → 감지 축소 배율 0.5 → 룬 탐색 주기 1.0초 |
| **창이 뜨자마자 바로 닫힘** | `run.bat` 은 이제 콘솔을 닫지 않고 오류를 보여주고 멈춥니다. 그 메시지를 확인하고, 아래 점검 명령을 실행하세요. 파이썬 예외는 `logs\crash.log` 에도 남습니다 |
| GUI 가 안 뜸 / 모듈 오류 | `.venv\Scripts\python -m rune_hunter --diagnose` 로 점검 → 모듈이 빠졌으면 `run.bat` 재실행(자동 재설치). 그래도 안 되면 `.venv` 폴더 삭제 후 `run.bat` |
| `Qt platform plugin could be initialized` | Microsoft Visual C++ 재배포 패키지(x64) 설치 후 재실행 |
| UAC 창이 안 뜸 | `run.bat` 을 우클릭 → `관리자 권한으로 실행` |

## 11. 안전 수칙

- 처음에는 **데모 모드**로 흐름을 확인한 뒤 실전에 적용하세요.
- `게임 창이 활성화된 경우에만 키 입력` 을 켜두면 다른 창으로 키가 새지 않습니다.

- 이 프로그램 사용으로 발생하는 모든 결과(제재·손해)의 책임은 사용자 본인에게 있습니다.
